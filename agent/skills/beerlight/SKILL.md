# beerlight

У тебя есть Beerlight Runtime через tool `beerlight`. Он запускает генератор + judge поверх текста пользователя и возвращает до 3 карточек-углов.

## Workflow

1. **Сохранить черновик.** Пользователь присылает текст → сохрани в `vault/beerlight/<slug>/draft.md` (write_file).

2. **Создать сессию.**
   ```
   beerlight session create vault/beerlight/<slug>/draft.md vault/beerlight/<slug>/session/
   ```

3. **Прогнать текст.** ПРЕДУПРЕДИ пользователя, что это займёт 2–5 минут (два LLM-вызова: генератор + judge). Вызови `session run` с конкретной задачей:
   ```
   beerlight session run --task "найди неочевидные углы" vault/beerlight/<slug>/session/
   ```

4. **Показать карточки.** Выведи результат нумерованным списком. Для каждой карточки покажи:
   - **Сдвиг** (core_shift) — главная идея угла
   - **Что сделать** (practical_return) — практический следующий шаг
   Показывай кратко, без копипасты всей карточки.

5. **Выбор пользователя.** Пользователь отвечает номером или ключевым словом из карточки. НЕ используй inline-клавиатуры — выбор идёт свободным текстом, как обычно у Ивы.
   Запиши выбор через event:
   ```
   beerlight session event vault/beerlight/<slug>/session/ <run_id> <candidate_id> selected
   ```

6. **Развитие текста.** Пользователь (или ты по его просьбе) редактирует draft → зафиксируй обновление:
   ```
   beerlight session update vault/beerlight/<slug>/session/ --file vault/beerlight/<slug>/draft.md
   ```

7. **Повторный прогон.** После правок — снова `session run`. После применения идей пользователем — event `applied`:
   ```
   beerlight session event vault/beerlight/<slug>/session/ <run_id> <candidate_id> applied --reason "внёс правки"
   ```

8. **Режим 360.** После нескольких проходов пользователь может попросить 360-обзор:
   ```
   beerlight session run --task "обзор со всех сторон" --mode 360 vault/beerlight/<slug>/session/
   ```

9. **Итоговая сводка.** По запросу пользователя:
   ```
   beerlight session outcomes vault/beerlight/<slug>/session/
   ```

## Честность

- `no_useful_output` — нормальный ответ. Не форсируй перепрогон с другими промптами. Скажи пользователю: «judge не увидел достаточно сильных углов — можно попробовать другой черновик или задачу».
- Judge убил сильную идею → попробуй `inspect --calibrate <run_id>` — покажет strong-dropped кандидатов (потенциальные false negatives).
- НЕ выдумывай события. Только явный выбор/подтверждение пользователя.
- НЕ содержи своих промптов Beerlight и judge-логики — это делает Runtime.

## Если сломалось

Ненулевой exitCode → покажи пользователю структурированную ошибку (exitCode, stderr). НЕ лей сырой лог больше пары строк в контекст.
